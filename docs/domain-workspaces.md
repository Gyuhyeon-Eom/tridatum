# 유형별 분석 화면

공개 화면은 네 유형 아래 12개 분야를 배치합니다. 각 분야는 상세 분석, 현황, 검토함으로 구성하며 전체 36개 화면입니다. 기본 화면은 상세 분석입니다. 실제 고객의 자료·성과를 대신 제시하지 않고 합성 원자료와 재현 가능한 계산으로 기능을 설명합니다.

| --------- | ---------------- | --------------------------------------------------------------------------------- |
| 상권·정책 | 상권 종합 분석   | 승인·취소·순매출, 동일점포 모집단, 점포 연결률, 영업일·도소매 구분                |

## 데이터와 동작

- 필터는 원천 기록을 선택하며, 필터를 좁혀도 같은 원장의 취소 금액·연결 정보가 달라지지 않습니다.
- 상세 대상 선택, 지역 군집·변수·구역 선택에 따라 관련 숫자·차트·표가 함께 바뀝니다.
- 검토함은 현재 분야·분석 조건의 작업을 보여줍니다. 세 확인 항목을 모두 체크하면 화면 내 완료를 기록합니다. 완료 상태 필터와 다시 열기를 제공합니다.
- 분야와 테마를 바꿔도 해당 분야의 선택·확인 기록을 유지합니다. 기록은 브라우저의 현재 페이지 메모리에만 있습니다.
- CSV는 현재 화면과 조건을 반영합니다. 상세 분석은 표의 열, 검토함은 작업·상태, 빈집 지역 분석은 선택 군집의 20개 변수와 예측·관측값을 내보냅니다.
- 굴뚝의 정상 자료 24/30 조건, 생활권 자원 배분, 계량기·거래 정합성의 수치는 예시 운영 규칙이며 법정 기준으로 표시하지 않습니다.

## 빈집 지역 분석의 계산

`scripts/generate-vacancy-data.py`가 고정 시드 907221로 600개 합성 지역과 20개 설명 변수를 생성합니다. 토지*전·토지*답·토지\_대, 노령화지수, 노후 건물 비율, 단독주택 비율, 인구 변화, 사용량, 접근성, 지가 등을 포함합니다.

학습 450개, 검증 150개를 분리합니다. 학습 자료로 표준화한 8개 지역 특성에 K-means를 적합하고 3개 군집을 생성합니다. 빈집률은 군집 입력에 포함하지 않습니다. 군집 이름은 적합한 중심 특성을 설명하는 라벨입니다.

Random Forest 회귀 모델은 20개 변수를 사용합니다. 검증 자료를 군집별로 나누고 변수마다 12회 순열 중요도를 계산합니다. 순위의 값은 MAE 증가(%p)이며, 증가·감소 방향이나 인과효과가 아닙니다. 상관된 변수 사이에는 중요도가 나뉠 수 있습니다. 변수 구간 차트는 선택 군집을 변수값 분위 구간으로 나눈 관측·예측 평균입니다.

모든 결과는 합성 데이터에서 얻은 예시이며 실제 지역의 예측 성과가 아닙니다. 지역 빈집률과 개별 건물의 빈집 가능성도 서로 다른 분석 단위입니다.

```sh
python3 scripts/generate-vacancy-data.py
node scripts/render-demos.mjs
node --test scripts/analytics.test.mjs scripts/solutions.test.mjs scripts/operations.test.mjs
```

## 코드 구성

- `operations-models.mjs`: 유형, 분야별 기준, 파생 집계와 검토 작업
- `operations-lenses.mjs`: 분야별 입력값·계산식·해석 조건
- `operations-view.mjs`: 상세 분석, 군집·변수 분석, 검토함, 화면별 CSV
- `vacancy-regions.mjs`: 생성한 군집·예측·검증·변수 중요도와 합성 지역
- `operations.css`: 유형·작업 탭과 분석 화면의 반응형 스타일

## 기술 근거

예시 구현에서 사용한 개념은 [scikit-learn의 순열 중요도](https://scikit-learn.org/stable/modules/permutation_importance.html)와 [군집 분석](https://scikit-learn.org/stable/modules/clustering.html#k-means), [Airflow의 재실행·파티션 원칙](https://airflow.apache.org/docs/apache-airflow/stable/best-practices.html), [Langfuse의 요청·관측·세션 구조](https://langfuse.com/docs/observability/data-model)를 확인했습니다. 외부 자료의 실제 기관·지역 데이터는 사용하지 않았습니다.
