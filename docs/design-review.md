# 공개 홈페이지 검수

## 2026-09-07 디자인 시스템 적용

제공된 밝은·어두운 디자인 문서와 미리보기에서 색상, 서체 계층, 간격, 모서리, 패널과 컴포넌트 규칙을 확인했습니다. 공개 화면은 흰색·회색·검은색을 기본으로 하고 노란색을 CTA와 선택 상태에 사용합니다. 공통 수치는 `assets/css/design-tokens.css`, 적용 원칙은 `docs/design-system.md`에 정리했습니다.

첫 화면은 압축 영문 표제와 입체 오브젝트, 내부 페이지는 어두운 바탕의 한글 표제로 구성했습니다. 큰 패널은 흑백으로 교대하고 서비스 목록은 한 항목씩 펼치는 아코디언으로 바꿨습니다. 서체 원본은 제공 파일에 없으므로 문서에서 제안한 Archivo와 한글용 Wanted Sans를 자체 제공합니다.

직접 모델링한 세 개의 프레임에는 DATA·MODEL·SYSTEM 표시를 적용했습니다. 무채색 재질과 작은 노란 중심부로 구성하며 버튼·포인터·스크롤에 반응합니다. 첫 화면에서만 WebGL 모듈을 불러오고 모션 감소·화면 밖·비활성 탭을 처리합니다. WebGL 실패 시 CSS 형태를 표시합니다.

12개 업무 화면에는 왼쪽 분야 메뉴와 오른쪽 작업 영역, 밝게·어둡게 전환을 적용했습니다. 모바일에서는 분야 선택 상자를 사용합니다. 테마는 CSS 변수만 바꾸므로 필터·선택 레코드·검토 표시가 유지됩니다.

## 실제 업무를 기준으로 한 예시

| 분야             | 담당자가 확인·조작하는 내용                                         |
| ---------------- | ------------------------------------------------------------------- |
| 상권 종합 분석   | 도매·소매, 기준 월, 시장별 매출·주말 비중, 지도와 상세 비교         |
| 빈집 예측        | 조사 권역, 건물별 예측 점수·에너지 사용·미사용 기간, 현장 조사 목록 |
| 굴뚝 모니터링    | 사업장·설비 선택, 온도·산소 추이, 수집 상태, 미래 24시간 중단 예측  |
| 방송 홍보 분석   | 프로그램 묶음, 방송 전후 8주와 전년 동기, 검색 관심도, 장소별 변화  |
| 돌봄 수요 분석   | 생활권별 수요·연계·정원·미연계, 공급 여력과 서비스 공백             |
| 교통·이동 분석   | 평일·주말, 거점 OD, 유입 순위, 시간대별 승하차                      |
| 환경·예찰 분석   | 우선 예찰·미점검 구역, 위험 점수, 신고·검체·현장 점검               |

| 위험징후 탐지    | 탐지 기준, 점검 목록, 근거 신호, 화면 내 확인 표시                  |
| 문서 검토 AI     | 문서함, 원문 인용 구간, 추출 필드 대조, 확인 표시                   |
| 데이터 운영      | 배치 상태, 수집·검증·적재 흐름, 격리 사유와 원천별 건수             |
| AI 운영 모니터링 | 조회 구간, 지연·오류·토큰, 요청 선택과 단계별 시간                  |

확인 가능한 프로젝트 설명·분석 노트에서 기능 흐름을 추출하고, 사용자 요청에 있던 돌봄 분석 등을 합성 예시로 구성했습니다. 기존 기관명, 실제 건물·개인 위치, 수행 성과 수치를 전용하지 않았습니다. 지도는 가상 공간 배치이며, 예측·판단 화면은 실제 업무 시스템에 연결되지 않습니다.

서비스 페이지의 예시도 상권 매출·빈집 조사·문서 원문 대조로 변경했습니다. 공통 분석 모듈은 별도 파일로 보존하고, 공개 첫 화면은 가상 업무 기록을 직접 집계합니다. 현재 선택 조건의 CSV를 내보낼 수 있습니다.

## 검증 항목

- 12개 업무 화면의 전환과 모든 조건 값에 대한 유효 수치
- 지도·목록과 상세 레코드의 연결, 문서 원문 대조·확인 표시
- 교통 OD·유입·승차·하차 총계 일치
- 돌봄 수요 = 연계 + 미연계, 입력 레코드 = 적재 + 격리
- CSV 기록 수·이스케이프·조건 반영
- 공통 모델·패널·요청 데이터 테스트 유지
- 모바일 분야 선택·차트·목록 스크롤, 공개 페이지의 가로 넘침
- 공개 페이지 전환, 뒤로 가기, 메뉴와 문의 폼 계약 보존

운영 Worker·관리자 UI·DNS·Access 설정은 변경하지 않습니다. GitHub 커밋 검토 후 기존 수동 배포 절차로 반영합니다.

## 검수 결과

- 기존 자동 테스트 11개 통과: 모든 조건의 수치, 레코드 연결, 집계 항등식, CSV 및 공통 분석 계산.
- 데스크톱에서 12개 분야를 어두운 테마로 전환하고 값·레이아웃을 확인했습니다. 브라우저 오류 로그는 비어 있습니다.
- 실제 브라우저 뷰포트 375px와 320px에서 12개 업무 화면의 가로 넘침이 없음을 확인했습니다. 표는 필요한 경우 자체 영역에서 스크롤됩니다.
- 모바일 공개 페이지 6개의 제목·입력 폼·메뉴를 확인했습니다. 아코디언은 선택한 항목 하나만 열립니다.
- 문서 선택 후 확인 표시를 추가하고 테마를 바꿔도 같은 문서와 표시가 유지됩니다.
- 문의 폼 ID·필드 6개, 개인정보처리방침 본문, 관리자 편집 키와 기본 문구를 기존 코드와 비교했습니다. 실서버 문의 제출은 실행하지 않았습니다.
- 페이지 이동 시 전환 레이어, 뒤로 가기 시 복원, 밝고 어두운 섹션에 따른 헤더 전환을 확인했습니다.

GitHub 변경을 검토한 뒤 기존 수동 배포 절차로 반영합니다. 이번 변경에서 운영 배포를 실행하지 않습니다.

## 유형별 상세 분석 추가 검수

공용 헤더에 td 심볼과 노란색 바탕을 적용하고 표제를 DATA INTO ACTION.으로 변경했습니다. 4개 유형·12개 분야 아래 상세 분석·현황·검토함을 구성했습니다. 분야별 차이는 `domain-workspaces.md`에 정리했습니다.

- 기존 11개 테스트와 신규 계산·기록·내보내기 검증 8개, 총 19개가 통과했습니다.
- 데스크톱에서 36개 화면을 전환하며 유효 수치와 가로 넘침을 확인했습니다.
- 375px 모바일에서 12개 분야의 상세 분석·검토함, 320px에서 12개 상세 분석 화면의 가로 넘침이 없음을 확인했습니다.
- 지역 군집 변경, 상위 변수 선택과 차트·정의·지역 값의 연결을 확인했습니다.
- 확인 항목을 채우기 전 완료 버튼은 비활성 상태이며, 완료 후 테마 전환·상태 필터에서도 기록이 유지됩니다.
